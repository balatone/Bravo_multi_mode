# Executive Summary

Provide the short version of the analysis: what was investigated, the key finding, and the preferred direction.

# Purpose / Question

State the problem to be solved, the decision to support, or the requirement being analyzed.

# Scope

Describe what is included in the analysis and what is explicitly out of scope.

## In Scope

- Items, systems, or behaviors analyzed.

## Out of Scope

- Items intentionally not covered.

# Current State

Summarize the existing system, process, data model, or implementation that is being analyzed.

# Methodology / Evidence

Explain how the analysis was performed and cite the evidence used.

- Source documents reviewed.
- Code, data, logs, or experiments inspected.
- Assumptions made during analysis.

# Findings

List the main observations and what they mean.

- Finding one.
- Finding two.
- Finding three.

# Evaluation Criteria

Explain the criteria used to compare options or judge the current state.

- Correctness.
- Feasibility.
- Maintainability.
- Complexity.
- Risk.

# Options / Recommendations

Present the candidate options, then state the preferred recommendation.

## Options Considered

- Option A — brief description.
- Option B — brief description.

## Recommended Direction

State the preferred approach and why it is preferred.

# Risks / Trade-offs / Constraints

Capture major risks, assumptions, constraints, and trade-offs that influence the recommendation.

- Risk one.
- Trade-off one.
- Constraint one.

# Supporting Materials / Evidence

Use this section for supporting material that is not already captured in `related_docs`.

Examples:

- Code paths.
- Diagrams.
- Datasets.
- Tickets.
- External sources.
- Companion `.notes.md` files.

# Next Steps

Describe the immediate follow-up actions or handoff items.

- Next step one.
- Next step two.

# Companion Notes / Raw Evidence

Detailed analysis, raw data, tables, calculations, code snippets, and exhaustive evidence should be stored in a separate companion file with the same base name and a `.notes.md` suffix.

Example: `RAD-001-demo-environment-definition.notes.md`

Use this main RAD document for the summary, decision, and high-level rationale only.
